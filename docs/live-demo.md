# Живая память: сценарий демонстрации

Центральный тезис: память агента можно исследовать как проверяемую историю
утверждений, а не только как список найденных фрагментов. Демонстрируются
источники, временная актуальность, противоречия и основания ответа.

## Запуск

```bash
python python/inspectable_demo.py --port 8766 --database outputs/live-demo.sqlite
```

Открыть http://127.0.0.1:8766/. SQLite-журнал создаётся автоматически.
Для чистого опыта нажать «Новая сессия»: старый журнал не удаляется, его можно
открыть по прежней ссылке с параметром `room`. Страница `/replay` сохраняет
предыдущий интерфейс с примерами LongMemCode.

## Сценарий: падение CI после Pydantic v2 за 45 секунд

1. **Пустая память.** Система отвечает «Недостаточно оснований». Отсутствие факта
   не трактуется как его отрицание.
2. **Старый код.** После обновления зависимости `UserOut.model_validate(db_user)`
   падает. Проектный `models.py` рекомендует `orm_mode = True` для Pydantic v1.
   На карте появляется источник и связанная с ним настройка.
3. **Противоречие.** Migration guide рекомендует `from_attributes = True` с V2,
   но совет из старого кода ещё не закрыт. При V2/K2 обе настройки действуют.
   Карта становится красной, а система не предлагает версионно случайный патч.
   Нажать узел: видны источник, текст свидетельства и причина решения.
4. **Разрешение во времени.** Нажать «Зафиксировать upgrade». Это явное действие
   посетителя, не автоматическое доверие более свежей записи. Старый интервал
   закрывается в V2, и актуальным патчем становится `from_attributes = True`.
   Старое утверждение не изменяется и не удаляется; добавляется событие замены.
5. **Два времени.** Переместить «Что уже было известно?» на K2: конфликт вернулся,
   поскольку замена ещё не была известна. Вернуться на K3 и выбрать V1:
   ответ снова `orm_mode = True`, потому что речь о Pydantic v1.
6. **Объяснимость.** Выбрать старый узел, посмотреть причину исключения и скачать
   JSON. Он содержит IDs, свидетельства, координаты, правила, ревизию и хеш
   объяснения. Повторный одинаковый запрос демонстрирует попадание в кэш.

## Что посетитель может проверить самостоятельно

- Записать `custom_adapter = True` для `staging`: это не конфликт со значением
  в `production`.
- Оставить начальную версию пустой: факт сохранится с неизвестной актуальностью,
  но строгий временной запрос его не выберет.
- Ввести явное отрицание `from_attributes = True` для того же объекта, свойства и
  окружения: оно конфликтует с положительным утверждением при пересекающихся
  интервалах.
- Для свойства `calls` несколько различных значений допустимы; они не считаются
  конфликтом просто потому, что различаются.
- Через инспектор подтвердить замену двумя собственными фактами. Перенос между
  объектами, свойствами или окружениями отвергается сервером.
- Обновить страницу или перезапустить сервер: факты и замены сохраняются.

## Границы интерпретации

Это живая работа памяти, **но не автономный LLM-агент**. Имена файла модели и
migration guide — метки происхождения учебных утверждений. Начальная история
полностью синтетическая и не выдаётся за дополнительный результат бенчмарка.
Свободный текст хранится как свидетельство; извлечение фактов из прозы не выполняется.
Значения пользовательской формы являются строками. Ответ отражает записанные
сведения, а не независимое установление истины.

Время действия — позиция в закреплённой линейной последовательности V0, V1, …,
не дата коммита и не порядок веток Git. Время поступления фиксируется сервером
в UTC. K обозначает отсечение по событиям записи. Инспектор показывает полный
журнал для анализа; записи, ещё не известные в выбранном K, отмечены отдельно
и не включаются в ответ. Последующие события не переписывают прежнее состояние знаний.

Реализация остаётся локальной и однопользовательской, использует исходные
проверенные правила `inspectable_memory.py` без изменения. Новый модуль
`live_memory.py` добавляет изоляцию рабочих сессий, обработку явных действий
и объяснимое представление результата. Для публичного многопользовательского
развёртывания нужны отдельные аутентификация, лимиты, транзакционная стратегия
конкурентных записей и эксплуатационная проверка; открывать текущий порт наружу нельзя.

## Проверки

```bash
uv run --frozen python -m pytest -q
uv run --with playwright python -m playwright install chromium
uv run --with playwright python experiments/smoke_live_ui.py --url http://127.0.0.1:8766/
```

Вместо загрузки тестового Chromium можно передать `--executable PATH_TO_CHROME`.
Тест создаёт отдельный пустой профиль, не открывает пользовательский. Он проходит
запись → конфликт → замену → оба временных среза, перезагрузку, разные окружения,
экранирование пользовательского текста, экспорт, мобильную ширину и новую сессию.
Снимки интерфейса и экспорт остаются локально в игнорируемой папке `outputs/ui/`.
